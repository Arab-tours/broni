# Столик — бронь столов в ресторанах Москвы

Сайт и приложение (PWA) для бронирования столов: 20 ресторанов из рейтингов WhereToEat Москва 2026, гида Michelin Moscow 2022 и Lemon Guide 2026, схема зала с занятыми и свободными столами, фильтры, карта, «Мои брони» с отменой.

**Стек:** чистый HTML/CSS/JS без сборки · GitHub Pages · Supabase (PostgreSQL) · Leaflet + OpenStreetMap.

## Что умеет

- **Каталог:** поиск, фильтры по району, кухне, среднему чеку, метро, «только со свободными столами», сортировка (лучшие, свободные, рядом со мной, цена).
- **Доступность в реальном времени:** на каждой карточке видно, сколько столов свободно на выбранные дату, время и число гостей. Данные обновляются каждые 30 секунд.
- **Карта:** метки ресторанов, цвет показывает, есть ли свободные столы.
- **Страница ресторана:** даты на 3 недели вперёд, слоты по 30 минут с числом свободных столов, схема зала (зоны, окна, бар, кабинки, общий стол). Можно нажать на стол и забронировать его.
- **Места у стойки:** для компании автоматически подбираются соседние свободные места.
- **Мои брони:** список и отмена. Брони привязаны к браузеру через секретный ключ, вход не нужен.
- **PWA:** приложение ставится на телефон («На экран Домой»), оболочка работает офлайн.

## Подключение базы (Supabase) — 5 минут

Пока база не подключена, сайт работает в **демо-режиме**: брони хранятся в браузере, занятость столов условная.

1. Зарегистрируйтесь на [supabase.com](https://supabase.com) и нажмите **New project** (регион — любой европейский).
2. Откройте **SQL Editor → New query**, вставьте весь файл [`supabase/schema.sql`](supabase/schema.sql) и нажмите **Run**.
3. Ещё раз **New query**, вставьте [`supabase/seed.sql`](supabase/seed.sql) и нажмите **Run**. Это загрузит 20 ресторанов и 373 стола.
4. Откройте **Project Settings → API** и скопируйте **Project URL** и **anon public key**.
5. Вставьте их в [`js/config.js`](js/config.js) и закоммитьте. Плашка «Демо-режим» исчезнет.

Anon-ключ публичный, его можно хранить в коде. Защита держится на правилах в базе:
- таблица броней закрыта целиком, имена и телефоны гостей наружу не отдаются;
- сайт работает только через функции `busy_slots`, `book_table`, `my_bookings` и `cancel_booking`;
- двойную бронь одного стола запрещает ограничение `EXCLUDE` в самой базе, гонки при одновременном нажатии невозможны;
- проверяются часы работы, вместимость стола, прошедшее время и горизонт 60 дней;
- на один телефон допускается не больше 5 активных броней;
- отменить бронь может только тот, у кого есть её секретный ключ.

## Публикация (GitHub Pages)

**Settings → Pages → Build and deployment → Deploy from a branch → `main` / `(root)`**. Сайт появится по адресу `https://arab-tours.github.io/broni/`.

## Как поменять рестораны

Все данные лежат в [`js/data.js`](js/data.js): адрес, кухня, средний чек, часы, координаты и схема зала (зоны и вместимость столов). После правок выполните:

```bash
node tools/make-seed.js
```

Скрипт пересоберёт `supabase/seed.sql`. Его нужно заново выполнить в SQL Editor, повторный запуск безопасен.

## Ограничения (честно)

- **Схемы залов примерные.** Рестораны не публикуют реальные планы. Зоны и число мест собраны по описаниям (например, около 110 мест у Probka, 77 у Onest, зал около 300 мест у Ruski), но расстановка столов условная.
- **Ресторан о брони не узнаёт.** Брони хранятся в нашей базе. Чтобы они доходили в ресторан, нужна интеграция с его системой (iiko, r_keeper, Restoplace и т. п.) или хотя бы уведомление администратору в Telegram или на почту.
- **Средний чек ориентировочный** (без напитков), по данным Restoclub, Яндекс Карт и обзоров 2025–2026 годов.
- Нет входа по SMS. «Мои брони» живут в браузере. Если очистить данные сайта, список пропадёт, но сами брони в базе останутся.
